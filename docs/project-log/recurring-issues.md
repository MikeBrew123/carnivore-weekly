## ISSUE-001 — Blog queue empty, no new posts publishing

**Symptom:** Site hasn't published a new blog post in several days. Daily GitHub Action runs green but nothing appears on the site.

**Has happened:** Feb 2026, Apr 2026 (5-day gap Apr 8-12), May 2026 (5-day gap Apr 26 – May 1)

**Decision tree:**
```
1. Check blog_posts.json:
   python3 -c "import json; d=json.load(open('data/blog_posts.json')); print(len([p for p in (d if isinstance(d,list) else d['blog_posts']) if p.get('status')=='ready']))"

   → If count > 0: go to ISSUE-002 (publish workflow not committing)
   → If count == 0: queue is empty. Writers need to generate content. → Fix below.

2. Check last published date:
   python3 -c "import json; d=json.load(open('data/blog_posts.json')); posts=sorted([p for p in (d if isinstance(d,list) else d['blog_posts']) if p.get('status')=='published'], key=lambda x:x.get('publish_date',''), reverse=True); print(posts[0]['publish_date'], posts[0]['title'][:50])"
```

**Root cause:** `autonomous_blog_generation.sh` requires interactive yes/no prompts — it was never automated. There is no scheduled task that generates new content. Every batch of posts was manually triggered in a CC session. When a session ended without generating the next batch, the queue ran dry.

**Fix (manual — temporary):** In a CC session, say "generate this week's blog content" to trigger the writer pipeline manually. Generates 9 posts (3 per writer), queues them with daily publish dates.

**Fix (permanent — ISSUE-001-FIX, NOT YET DONE):** Refactor `scripts/autonomous_blog_generation.sh` and `scripts/generate_weekly_content.py` to accept a `--auto` flag that skips all `input()` prompts. Then schedule a weekly local task (Sunday evening) that runs it unattended. See Beads issue for tracking.

**Current status:** ✅ FIXED (2026-05-01) — Weekly local scheduled task `weekly-blog-content-generation` created. Runs every Sunday at 8pm, invokes Chloe for research then Sarah/Marcus/Chloe to write 9 posts, commits and pushes. Daily publisher handles the rest. `--auto` flag added to `generate_weekly_content.py` to prevent any future `input()` blocks.

**Next run:** Sunday 2026-05-03 at 8pm.

**Last worked on:** 2026-05-01

## ISSUE-002 — daily_publish.py runs but new posts not committed to git

**Symptom:** Posts are in blog_posts.json with status="ready", daily action runs green, but the HTML files don't appear in the repo and the site doesn't update.

**Has happened:** Apr 8–12, 2026 (5-day silent failure)

**Decision tree:**
```
1. Check if posts have status="ready" (see ISSUE-001 tree)
2. Check git log for recent daily-publish commits:
   git log --oneline --grep="daily publish" -10
3. If no commits in last 24h despite ready posts → this is the bug.
4. Check .github/workflows/daily-publish.yml for this pattern:
   - git add -A          ← REQUIRED
   - git diff --staged   ← must be --staged, not plain --diff
```

**Root cause:** The original workflow used `git diff --name-only` which only shows modifications to already-tracked files. New HTML files generated by `generate_blog_pages.py` are untracked — they're invisible to this command. The workflow ran, generated files, then saw "no changes" and didn't commit.

**Fix (applied Apr 13, 2026, commit 208b5ab):** Changed workflow to `git add -A` first, then `git diff --staged --name-only`. This detects new untracked files.

**Current status:** ✅ FIXED — verify with `cat .github/workflows/daily-publish.yml | grep "git add"` — should show `git add -A`.

**Do NOT:** Revert to `git diff --name-only` for any reason.

## ISSUE-003 — GitHub Actions fails because script committed to repo but dependencies aren't

**Symptom:** GitHub Actions workflow fails with "file not found" or "module not found". Works locally.

**Has happened:** Apr 5, 2026 (gsc-request-indexing.js created locally, never committed)

**Decision tree:**
```
1. Check the error — which file is missing?
2. git status — is it untracked?
3. git log --oneline -- <filename> — was it ever committed?
```

**Root cause:** Script created locally during a session, referenced in workflow, but `git add` was never run for that file. Works locally because the file exists on disk. Fails in CI because the file isn't in the repo.

**Rule:** Any file referenced in `.github/workflows/` must be committed before the workflow runs. Run `git status` before pushing workflow changes.

**Current status:** ✅ FIXED (Apr 5, 2026). Rule encoded here for future reference.

## ISSUE-004 — Homepage stuck on stale week / wrong YouTube videos

**Symptom:** Homepage shows "Week of [old date]" despite weekly update running. YouTube videos are wildlife/unrelated content.

**Has happened:** ~Apr 5, 2026

**Root cause:** Two scripts were both calling the YouTube API. The secondary script ran first and burned the daily quota. When the main collector ran, it hit the quota limit and fell back to cached/stale data. Stale AI-generated dates weren't being corrected.

**Fix:** Deleted the secondary quota-burning script (`generate_weekly_topics.py`). Single-agent architecture — one YouTube API call per weekly run.

**Current status:** ✅ FIXED. If it recurs, check for any script calling `youtube.search()` outside of the main weekly update pipeline.

## ISSUE-005 — Sitemap not updating when new posts are published

**Symptom:** New posts are live on the site but not in the sitemap. Google can't discover them via sitemap crawl.

**Has happened:** Apr 2026 (3 posts invisible to Google for 1+ week)

**Root cause:** Sitemap regeneration wasn't part of the daily-publish workflow. Posts were published but the sitemap pointed to the old set of URLs.

**Fix:** `generate_blog_pages.py` now regenerates the sitemap as part of every run. `daily_publish.py` calls `generate_blog_pages.py` on every publish.

**Workaround (if sitemap is stale):** Run `python3 scripts/generate_blog_pages.py` locally, commit, push.

**Current status:** ✅ FIXED in pipeline. Weekly GSC indexing routine (scheduled Friday 9am) catches any stragglers and submits them to Google directly.
